# JARVIS — Тестирование

Правило: не считаем «работает», пока это не проверено. Успешная компиляция — не доказательство.

## 1. Уровни

| Уровень | Инструмент | Где | Что проверяет | Статус |
|---|---|---|---|---|
| Unit | Swift Testing (`swift test`) | CI macOS, локально | логика модулей без UI и системных API | ✅ Phase 1 |
| Security | Swift Testing + privacy-lint | CI | политика подтверждения, валидатор аргументов, реестр, запрещённые API | ✅ Phase 1 |
| Privacy | Swift Testing + privacy-lint | CI | `Utterance`/`Sensitive` не раскрываются, логгер не пишет текст ошибок, аудит без деталей, приватные значения по умолчанию | ✅ Phase 1 |
| UI | XCUITest | CI macOS, локально | запуск, статус, включение/выключение, индикатор микрофона | ✅ Phase 1 (базовый) |
| Integration | Swift Testing с фейковыми движками | CI | оркестратор: wake word → STT → правило → инструмент → аудит | Phase 2–3 |
| Performance | XCTest `measure` + Instruments | Mac пользователя | RAM/CPU/задержки по [PerformanceTargets.md](PerformanceTargets.md) | Phase 2, 5 |
| Regression | весь набор в CI на каждый push | CI | ничего не сломалось | ✅ с Phase 1 |
| Manual | чек-листы ниже | Mac пользователя | то, что нельзя проверить в CI (микрофон, TCC, голос) | каждая фаза |

## 2. Что покрыто сейчас (Phase 1)

* `AssistantStateMachineTests` — все переходы, «выключить из любого состояния», пауза микрофона,
  перебивание, ошибки.
* `PrivacyTypesTests` — `Utterance` не печатается, не дампится, не сериализуется; `Sensitive` скрыт.
* `JarvisLoggerTests` — формат, уровни, ошибки логируются без текста.
* `AuditLogTests` — запись/чтение, минимальный и подробный режимы, санитизация, права 0600,
  срок хранения, очистка, повреждённые строки; `ActionIdentifierTests`.
* `StorageTests` — права папок/файлов, атомарная запись, резервные копии.
* `SettingsTests` — приватные значения по умолчанию, Privacy Mode блокирует облако,
  нормализация, хранение, отсутствующие поля, повреждённый файл, защита файла новой версии,
  миграции с резервной копией.
* `ToolRegistryTests`, `ArgumentValidatorTests`, `ConfirmationPolicyTests` — тесты безопасности
  инструментов, включая перебор всех комбинаций для опасных действий.
* `scripts/test-privacy-lint.sh` — каждое правило ловит нарушение и не даёт ложных срабатываний.
* `LaunchUITests` — запуск, статус «Выключен» → «Готов» → «Выключен», честное сообщение
  о том, что голоса пока нет, индикатор микрофона.

## 3. Запуск

```bash
make test
```

```bash
make test-ui
```

UI-тесты при первом запуске попросят разрешить Xcode/тест-раннеру управление компьютером
(Accessibility) — это нужно XCUITest, а не JARVIS.

## 4. Ручной чек-лист Phase 1

- [ ] `make run` — в строке меню появилась иконка, открылось окно JARVIS.
- [ ] Нет иконки в Dock.
- [ ] «Включить» → статус «Готов», в журнале «JARVIS включён»; «Выключить» → «Выключен».
- [ ] «Пауза микрофона» доступна только во включённом состоянии.
- [ ] Индикатор показывает «Микрофон не используется»; системного оранжевого индикатора нет.
- [ ] Privacy Mode в меню включается/выключается и отражается в журнале и в иконке щита.
- [ ] Настройки (⌘,): имя ассистента сохраняется после перезапуска.
- [ ] Автозапуск: переключатель появляется в «Системные настройки → Основные → Объекты входа».
- [ ] Журнал действий: записи есть, «Очистить…» удаляет их (и файлы в `audit/`).
- [ ] Испортить `settings.json` вручную → при запуске уведомление о восстановлении,
      в `backups/` есть копия испорченного файла.
- [ ] Ни один файл в `~/Library/Application Support/JARVIS` не содержит ничего, кроме
      настроек и событий журнала.
- [ ] Activity Monitor: JARVIS в простое ~0% CPU; записать фактический RAM в PerformanceTargets.md.

## 5. Принципы

* Тесты не обращаются к сети и не трогают реальные данные пользователя (временные папки,
  флаг `--ui-testing`).
* Время в тестах — управляемые часы (`TestClock`), а не `Date()`.
* Каждая новая функция — с тестами; каждая найденная ошибка — с регрессионным тестом.
* Результаты не подгоняются: упавший тест чинится или честно документируется.
