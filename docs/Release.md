# JARVIS — Релизы и обновления

> Статус: план. Ничего из этого ещё не выполнено: приложение **не подписано Developer ID и
> не нотаризовано**. Платные аккаунты без решения пользователя не создаются.

## 1. Версионирование

* [SemVer](https://semver.org/lang/ru/): `MAJOR.MINOR.PATCH`. До 1.0 — `0.<фаза>.<патч>`:
  Phase 1 = `0.1.x`, Phase 2 = `0.2.x`…
* `MARKETING_VERSION` (что видит пользователь) и `CURRENT_PROJECT_VERSION` (номер сборки,
  монотонно растёт) — в `project.yml`.
* Каждый релиз — git-тег `vX.Y.Z` и запись в [CHANGELOG.md](../CHANGELOG.md).

## 2. Способы распространения

| Вариант | Нужно | Что получает пользователь |
|---|---|---|
| Собрать самому (`make run TEAM=…`) | бесплатный Apple ID | работает на своём Mac, разрешения стабильны |
| DMG с ad-hoc подписью | ничего | Gatekeeper блокирует запуск; разрешить вручную в «Конфиденциальность и безопасность» |
| **DMG с Developer ID + нотаризация** | Apple Developer Program, $99/год | обычная установка без предупреждений, автообновления |
| Mac App Store | — | невозможно: JARVIS работает без App Sandbox (см. Security.md §10) |

Рекомендация: для личного использования достаточно первого варианта. Developer ID нужен,
если приложение будут ставить другие люди.

## 3. Требования Apple (Developer ID)

1. **Сертификат Developer ID Application** (в Apple Developer Program).
2. **Hardened Runtime** — уже включён в проекте (`ENABLE_HARDENED_RUNTIME`).
3. **Подпись** всего бандла, включая вложенные фреймворки (Sparkle) — `codesign --options runtime`.
4. **Нотаризация**: `xcrun notarytool submit JARVIS.dmg --keychain-profile <профиль> --wait`,
   затем `xcrun stapler staple JARVIS.dmg`.
5. Без `get-task-allow` в Release, минимальные entitlements.

Секреты (пароль приложения Apple ID / API-ключ App Store Connect, приватный ключ Sparkle)
хранятся только в Keychain разработчика или в зашифрованных секретах CI — никогда в репозитории.

## 4. Обновления (Phase 6)

**Sparkle 2** (единственная планируемая сторонняя зависимость):

* приложение раз в сутки (по настройке; при первом запуске — вопрос пользователю) скачивает
  `appcast.xml` с GitHub Releases по HTTPS — это статический файл, не наш сервер;
* каждое обновление подписано **EdDSA** (ключ разработчика); Sparkle дополнительно сверяет
  подпись кода новой версии со старой;
* поддерживаются дельта-обновления;
* сбор «профиля системы» Sparkle выключен (`SUEnableSystemProfiling = NO`);
* в Privacy Mode автоматические проверки можно отключить.

Ошибки обновления: при сбое скачивания/проверки подписи Sparkle не трогает установленную
версию; пользователь видит сообщение и может повторить позже.

## 5. Миграции данных и откат

* Настройки, память, сценарии — JSON с `schemaVersion`. Перед миграцией файл копируется в
  `backups/<имя>.v<старая версия>.<время>.json` (уже реализовано для настроек).
* Добавление полей не требует миграции (у всех полей есть значения по умолчанию).
* Файл более новой схемы старая версия **не перезаписывает** (реализовано) — это делает
  откат безопасным.
* Откат: скачать предыдущий релиз с GitHub Releases и установить поверх; при необходимости
  восстановить файл из `backups/`. Кнопка «вернуть предыдущую версию» — кандидат на Phase 6+.
