# JARVIS — Приватность: исследование, гарантии, ограничения

Этот документ — обязательное исследование перед реализацией голоса (требование §8.8 ТЗ).
Мы **не** заявляем «100% анонимность» и «утечка невозможна». Ниже — что гарантирует
архитектура, как это проверяется и какие риски остаются.

## 1. Какое API используется для распознавания речи

**`SpeechAnalyzer` (macOS 26+) с модулями:**

| Модуль | Роль | Где работает |
|---|---|---|
| `SpeechDetector` | VAD: есть ли речь | on-device |
| `SpeechTranscriber` | основной STT для поддерживаемых языков | on-device; модели — системные ассеты |
| `DictationTranscriber` | fallback для языков, которых нет у `SpeechTranscriber` | on-device: по документации Apple использует те же модели, что системная диктовка и `SFSpeechRecognizer` в on-device режиме, и **не поддерживает языки, доступные только через сеть** |

**`SFSpeechRecognizer` запрещён в коде** (проверяется privacy-lint в CI). Причина: по
документации флаг `requiresOnDeviceRecognition` соблюдается только если
`supportsOnDeviceRecognition == true`. Ошибка в этой проверке — и аудио может уйти на серверы
Apple. Новые модули такой ветки не имеют.

Что проверяется во время работы (Phase 2):

1. `SpeechTranscriber.isAvailable` и `supportedLocales`/`installedLocales` для выбранного языка;
   если язык не поддержан — `DictationTranscriber`.
2. Если ни один модуль не поддерживает язык локально — JARVIS **не** отправляет звук никуда,
   а сообщает об ограничении и предлагает другой язык или текстовый ввод.
3. Если модель языка не установлена — запрос на скачивание через `AssetInventory`
   с явным объяснением (скачивается модель от Apple; **звук и текст не передаются**).

**Разрешение «Распознавание речи».** Документация Apple и сторонние источники расходятся в
том, нужно ли оно для `SpeechAnalyzer`. Поэтому JARVIS запрашивает только микрофон, а
разрешение на распознавание — **только если без него распознавание не заработало**: показывается
кнопка «Разрешить распознавание». Системный текст этого запроса macOS может упоминать отправку
речи Apple — это общий текст системы; JARVIS по-прежнему распознаёт только на устройстве.
Устаревший класс распознавателя используется исключительно для чтения/запроса статуса
разрешения (две строки с явным исключением privacy-lint).

Особенности Apple Silicon (M1/M2 Pro и новее): все перечисленные модули поддерживаются;
фактический список языков зависит от версии macOS и выясняется на устройстве.

## 2. Какие данные обрабатываются локально

Всё, кроме явно перечисленного в §3:

* аудио с микрофона — только кольцевой буфер в RAM (~2 с) и потоковая передача в STT;
* расшифровки (wake word и команды) — тип `Utterance` в RAM;
* интерпретация, план, выполнение инструментов;
* память о предпочтениях, сценарии, настройки, журнал аудита — файлы на Mac;
* TTS — `AVSpeechSynthesizer` на устройстве;
* локальные LLM: Apple Foundation Models (on-device модель ОС) или сервер на `localhost`.

## 3. Какие данные могут передаваться наружу

| Данные | Кому | Когда | По умолчанию |
|---|---|---|---|
| Текст команды + описания инструментов + минимальный контекст | выбранный облачный провайдер (Anthropic/OpenAI) | только Cloud/Hybrid **и** согласие **и** не Privacy Mode | **выключено** |
| Содержимое писем/файлов для сводки | облачный провайдер | только при отдельном согласии на конкретную операцию | **выключено** |
| Запрос на скачивание языковой модели | Apple (системный `AssetInventory`) | при первом использовании языка, с объяснением | только по действию пользователя |
| Адрес сайта / поисковый запрос | открывается **в браузере пользователя** (выбранная поисковая система) | только по явной команде «открой сайт…», «найди в интернете…» | только по команде; сам JARVIS в сеть не ходит |
| Проверка обновлений (версия приложения) | GitHub Releases (Phase 6) | по настройке; при первом запуске — вопрос | спрашиваем |
| Запросы к локальному LLM-серверу | процесс Ollama/LM Studio на этом Mac | если выбран | — |

**Никогда:** аудио, история команд, расшифровки, телеметрия, идентификаторы устройства.

Про облачных провайдеров: что они хранят и сколько — определяется их условиями (API Terms,
политики хранения данных). JARVIS не утверждает, что данные «нигде не сохраняются»; в окне
согласия показывается ссылка на политику провайдера и точный текст, который будет отправлен.

Про локальный LLM-сервер: это стороннее приложение, которое пользователь ставит сам; его
сетевое поведение — ответственность его разработчиков (стоит проверить его настройки).

## 4. Как исключается сохранение аудио и расшифровок

| Механизм | Что даёт |
|---|---|
| В коде нет API записи аудио на диск (`AVAudioFile(forWriting:)`, `AVAudioRecorder`) | privacy-lint в CI падает при их появлении |
| Аудиобуферы живут только в RAM и сразу передаются модели; в режиме wake word ворота тишины держат не больше ≈0,5 с звука «до» (6 буферов), старые выбрасываются | нет накопления |
| `Utterance` **не** `Codable`, `description`/`debugDescription`/`Mirror` — `<redacted>` | расшифровку нельзя случайно сериализовать, напечатать или показать в отладчике через `dump` |
| Логгер принимает только `StaticString` и числа/флаги | расшифровку невозможно передать в лог — это ошибка компиляции |
| Ошибки логируются как тип+код, без `localizedDescription` | текст команды не утечёт через сообщение об ошибке |
| Аудит пишет идентификатор инструмента, а не команду | история действий без истории речи |
| Краткосрочный контекст диалога — только RAM, TTL (по умолчанию 2 мин), очищается при выключении | нет «истории диалогов» на диске |
| В режиме wake word текст без фразы-активатора сразу отбрасывается; в памяти остаются максимум 3 последних слова (если «привет» и «джарвис» попали в разные фрагменты) | фоновая речь не накапливается даже в RAM |
| Распознанный текст команды показывается в окне только во время прослушивания; последний ответ исчезает через несколько минут | на экране не остаётся истории |
| Нет восстановления состояния окон для полей ввода команд; поля без автосохранения | macOS не сохранит текст в saved state |
| Буфер обмена не используется для передачи команд | текст не останется в pasteboard |
| Окно подтверждения и вопрос «Точно закрыть «Safari»?» живут только в памяти; в журнал пишется идентификатор действия и результат (выполнено / отменено), в подробном режиме — имя приложения или сайта, но не поисковый запрос | вопросы и ответы не накапливаются |
| Самодиагностика «Где тратится процессор» читает только время процессора: потоков JARVIS и системных процессов со словом «speech» в имени. Отчёт копируется в буфер обмена только по кнопке и содержит лишь имена потоков/процессов и проценты | никаких данных о речи; ничего не сохраняется и не отправляется |
| `URLSession` с `ephemeral`-конфигурацией | ответы облака не попадают в дисковый HTTP-кеш |
| Нет сторонних SDK аналитики и крэш-репортинга | privacy-lint запрещает известные SDK |
| Тот же код в Debug и Release | «режим разработки» не пишет больше |

## 5. Логи, кеш, аналитика, крэш-репорты

* **Unified Logging (`os.Logger`)** — только через фасад `JarvisLogger`; сообщения —
  статические строки, значения — числа/флаги/статические токены, поэтому всё помечено
  `public` безопасно.
* **Крэш-репорты macOS** (ReportCrash) содержат стек вызовов и состояние регистров,
  а не содержимое кучи. Для приложений вне App Store Apple не пересылает их разработчику;
  пересылка Apple зависит от системной настройки «Отправлять аналитику Mac» пользователя.
* **Аналитика** — отсутствует.
* **Кеш** — дисковых кешей нет (см. ephemeral URLSession).

## 6. Privacy Mode

Включается одной кнопкой в меню (и горячей клавишей — Phase 2):

* запрещена любая сетевая обработка AI и голоса (облачные провайдеры недоступны, без исключений);
* используются только локальные функции;
* команды и расшифровки не сохраняются (как и всегда);
* микрофон можно мгновенно поставить на паузу; индикатор в меню показывает состояние.

Индикация микрофона: собственный индикатор в строке меню + системный оранжевый индикатор
macOS, который приложение отключить не может (это хорошо: пользователь видит правду).

## 7. Автоматические проверки

`scripts/privacy-lint.sh` (запускается в CI и локально через `make lint`) падает, если в
исходниках приложения и пакетов (не в тестах) встречается:

| Правило | Почему |
|---|---|
| `print(`, `debugPrint(`, `dump(`, `NSLog(` | обход privacy-safe логгера |
| `os_log(` / `Logger(` вне файла логгера | обход фасада |
| `SFSpeechRecognizer` | возможная серверная обработка звука |
| `AVAudioRecorder`, `AVAudioFile(forWriting` | запись звука на диск |
| `URLSession.shared`, `URLSessionConfiguration.default` | дисковый кеш/cookies |
| `UserDefaults` | данные должны жить в прозрачных файлах JARVIS |
| импорты Firebase/Sentry/Crashlytics/Mixpanel/Amplitude/Segment | телеметрия |

Исключение возможно только с комментарием `// privacy-lint:allow <правило> — <причина>`
в той же строке — это видно на ревью.

Юнит-тесты приватности (Swift Testing): `Utterance` не печатается и не сериализуется;
логгер не выводит текст ошибок; аудит в минимальном режиме не сохраняет детали;
настройки по умолчанию приватны (локальный AI, облако выключено, согласие на каждый запрос).

## 8. Чек-лист аудита приватности (перед каждым релизом)

- [ ] privacy-lint и все тесты зелёные в CI.
- [ ] В `~/Library/Application Support/JARVIS` нет файлов с текстом команд (поиск по
      произнесённой тестовой фразе: `grep -r "тестовая фраза" ~/Library/Application\ Support/JARVIS`).
- [ ] `log show --predicate 'subsystem == "io.github.kornegy.jarvis"' --last 1h` не содержит
      текста команд.
- [ ] Little Snitch / LuLu (или `nettop`): при выключенном облаке и обновлениях — нет
      исходящих соединений, кроме скачивания модели языка по запросу.
- [ ] В Privacy Mode облачный провайдер недоступен даже при наличии ключа.
- [ ] Новые зависимости и entitlements обоснованы в документации.
- [ ] Окно согласия на облако показывает провайдера, точный текст и ссылку на политику.
- [ ] Удаление памяти и журнала из UI действительно удаляет файлы.

## 9. Остаточные риски и то, что нельзя гарантировать

1. **Затирание памяти.** Строки Swift копируются и не затираются гарантированно; данные могут
   оставаться в RAM до перезаписи. Swap и файл гибернации шифруются macOS (с FileVault).
2. **Внутреннее поведение фреймворков Apple.** Мы опираемся на документацию: модули
   SpeechAnalyzer работают on-device. Что системные компоненты делают с метриками
   использования, мы проверить не можем. Рекомендация: выключить «Улучшать Siri и
   Диктовку» в системных настройках.
3. **Облачные провайдеры** хранят данные по своим правилам; после отправки текст вне нашего
   контроля.
4. **Скомпрометированный Mac** (вредоносный процесс с правами пользователя, кейлоггер,
   другие приложения с доступом к микрофону) — вне возможностей JARVIS.
5. **Скачивание моделей** раскрывает Apple факт использования языка.
6. **Люди рядом** слышат ответы TTS — для приватных ответов будет режим «только текст».
