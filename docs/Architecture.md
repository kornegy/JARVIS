# JARVIS — Архитектура

> Статус: Phase 0 (исследование и архитектура) завершена; идёт Phase 1 (фундамент проекта).
> Документ описывает **целевую** архитектуру. Что уже реализовано, смотри в [Roadmap.md](Roadmap.md).

## 1. Коротко

JARVIS — нативное macOS-приложение на **Swift 6 + SwiftUI/AppKit**, живущее в строке меню.
Оно работает **в одном процессе**, без собственного сервера, хранит всё локально и
обращается к сети только тогда, когда пользователь явно включил облачный AI и дал согласие.

Главные идеи:

1. **Local first.** Распознавание речи, wake word, простые команды, управление macOS,
   память и настройки — на Mac. Облако — опционально и только для текста.
2. **AI предлагает — исполнитель решает.** Модель (локальная или облачная) возвращает
   только *план* из вызовов заранее описанных инструментов. Каждый вызов проходит
   валидацию, проверку разрешений и политику подтверждения в локальном исполнителе.
   Shell, произвольный код и «сырые» AppleScript из ответа модели невозможны в принципе.
3. **Приватность по типам.** Расшифровка команды живёт в типе `Utterance`, который нельзя
   закодировать в JSON, а логгер физически не принимает произвольные строки.
   Аудио обрабатывается только в оперативной памяти.
4. **Тяжёлое — лениво.** Нет постоянного LLM-инференса. Микрофон открыт только когда
   ассистент включён; распознавание гейтится детектором голоса (VAD); модели выгружаются
   при простое.

## 3. Голосовой конвейер

```
Микрофон (AVAudioEngine)
  → конвертация в формат модели (только RAM)
  → [режим wake word] ворота тишины SpeechGate: громкость ниже порога → звук не идёт
     дальше; держим в RAM только ≈0,5 с «до», чтобы не потерять начало слова
  → VAD (SpeechDetector) — «есть ли речь?»; тишина не транскрибируется
  → потоковое on-device STT (SpeechAnalyzer: SpeechTranscriber или DictationTranscriber)
  → WakePhraseMatcher («привет джарвис», «джарвис», «hey jarvis»…)
       ├─ нет фразы → текст немедленно отбрасывается
       └─ есть фраза → состояние Listening → дослушиваем команду до паузы
  → Utterance (только RAM) → интерпретация → план → исполнитель → ответ (TTS)
  → Utterance, буферы и план освобождаются
```

* **Push-to-Talk**: глобальная горячая клавиша (Carbon `RegisterEventHotKey` — не требует
  разрешения Accessibility). В режиме «только PTT» микрофон закрыт до нажатия.
* **Почему wake word через STT, а не отдельной моделью** — см.
  [TechnologyComparison.md §4](TechnologyComparison.md#4-wake-word). Кратко: ноль
  зависимостей, любой язык и любая фраза (требование «сменить wake word»), всё локально.
  Цена — CPU при постоянной речи рядом (ТВ, созвоны). Если замеры в Phase 2/5 превысят
  цели из [PerformanceTargets.md](PerformanceTargets.md), добавляем первую ступень —
  крошечную Core ML-модель keyword spotting (двухступенчатая схема).
* **Конец фразы**: пауза 0,8–1,2 с (настраивается) или лимит 15 с. Отпустили клавишу PTT
  или ворота тишины закрылись — просим модель сразу выдать окончательный текст
  (`SpeechAnalyzer.finalize`), а не ждать следующего звука.
* **Экономия процессора** (после замера 44 % на Mac пользователя, см.
  [PerformanceTargets.md §4](PerformanceTargets.md#4-измерено)):
  - ворота тишины в режиме wake word — в тишине модель распознавания не работает вовсе;
  - пока пользователь явно говорит команду (после фразы-активатора или по кнопке), ворота
    открыты принудительно — тихая речь не обрезается;
  - без опций «максимально быстрых» результатов (`fastResults`, `frequentFinalization`) —
    модель реже пересчитывает текст;
  - постоянное прослушивание работает с приоритетом `.utility`, модели держатся в памяти
    недолго (`.lingering`), чтобы повторное нажатие PTT не загружало их заново;
  - выбор модели в настройках («Автоматически» / «Новая модель Apple» / «Классическая») —
    чтобы сравнить нагрузку и качество на конкретном Mac.
* **Самоактивация**: на время собственной речи (TTS) JARVIS не слушает команды. Voice
  processing (эхоподавление) отложено: на macOS он приглушает звук других приложений.

## 4. Интерпретация команды (AI Layer)

```
Utterance
  │
  ├─► 1. RuleIntentParser (локально, детерминированно, RU/EN, < 5 мс)
  │      «открой Safari», «громкость 30», «найди файл диплом», «который час»…
  │      уверенное совпадение → готовый план, LLM не нужен
  │
  └─► 2. HybridRouter выбирает LLM-провайдера по правилам (§5)
         вход:  текст команды + каталог инструментов + минимальный контекст
         выход: план = [ToolCall] и/или текстовый ответ
  │
  ▼
PlanValidator → для каждого шага:
  ToolRegistry.lookup → ArgumentValidator → PermissionManager → ConfirmationPolicy
  → (подтверждение голосом/кнопкой) → Tool.run → AuditLog → результат
```

* Каталог инструментов передаётся модели в детерминированном порядке (стабильный префикс
  для кеширования промпта у облачных провайдеров).
* Результаты инструментов, содержащие внешний контент (файлы, письма, страницы), помечаются
  как **недоверенные** (taint). Если план «испачкан», любое действие с побочным эффектом
  требует подтверждения, независимо от настроек. Подробно — [Security.md §6](Security.md).
* Ответ пользователю: короткие шаблоны с учётом «личности» (юмор/формальность/
  разговорчивость) локально; для свободной беседы — текст LLM.

## 5. Hybrid AI: локально, облако, гибрид

| Режим | Что используется | Сеть |
|---|---|---|
| **Local** (по умолчанию) | правила → Apple Foundation Models (если доступна и поддерживает язык) → локальный сервер (Ollama/LM Studio, OpenAI-совместимый API на `localhost`) | нет |
| **Cloud** | правила → облачный провайдер (Claude / OpenAI) | да, по согласию |
| **Hybrid** | правила → локальная модель → облако только если задача сложная/локальная модель не справилась/недоступна | по согласию |

Правила `HybridRouter` (в порядке приоритета):

1. **Privacy Mode** включён → облако запрещено, без исключений.
2. Сработало правило → LLM не вызывается вообще.
3. Нет согласия на облачного провайдера или нет ключа в Keychain → облако недоступно.
4. Нет сети (`NWPathMonitor`) → только локально, без ожидания таймаутов.
5. Задача требует длинного контекста (сводка 10 писем, анализ кода) или локальная модель
   вернула невалидный план 2 раза подряд → кандидат на облако (в Hybrid) → **запрос
   согласия** с показом того, что именно уйдёт и кому.
6. Иначе — локальная модель.

Минимизация данных для облака: только текст команды, описания инструментов и минимально
необходимый контекст. **Никогда**: аудио, история команд, содержимое файлов/писем без
отдельного согласия на конкретную операцию.

### 5.1. Оценка стоимости облачного AI

Цены — с официальных страниц на ноябрь 2026, за 1 млн токенов (input / output).
Перед включением всегда сверяй актуальный прайс провайдера.

| Модель | Input | Output | Типичная команда* | 20 команд/день (≈600/мес) | 100 команд/день (≈3000/мес) |
|---|---|---|---|---|---|
| Claude Haiku 5.5 | $0.10 | $0.50 | ≈ $0.001 | ≈ $0.6 / мес | ≈ $3 / мес |
| Claude Sonnet 5.5 | $2 | $10 | ≈ $0.02 | ≈ $12 / мес | ≈ $60 / мес |
| Claude Opus 5.5 | $4 | $20 | ≈ $0.04 | ≈ $24 / мес | ≈ $120 / мес |
| OpenAI (малые модели)** | ~$0.05–0.25 | ~$0.4–2 | ≈ $0.001–0.005 | ≈ $0.6–3 / мес | ≈ $3–15 / мес |

\* Типичная «сложная» команда = 2 обращения к модели × (≈3 000 входных токенов: системный
промпт + каталог ~25 инструментов + контекст; ≈400 выходных, включая рассуждение).
Кеширование стабильного префикса снижает стоимость входа, но у моделей есть минимальный
размер кешируемого префикса — эффект нужно замерить, а не обещать.
\*\* Цены OpenAI взяты из сторонних агрегаторов и не подтверждены по официальной странице —
до выбора OpenAI их нужно перепроверить.

Ключевое: в режиме Hybrid большинство команд («открой», «найди», «громкость») обрабатываются
правилами и стоят $0. Реальный счёт определяется только сложными запросами.
Модель по умолчанию для Claude — `claude-opus-5-5`; выбор более дешёвой (Sonnet 5.5,
Haiku 5.5) — решение пользователя в настройках.

## 6. Почему не нужен собственный сервер

Сервер решает задачи, которых у JARVIS на старте нет:

| Задача, для которой обычно нужен сервер | У JARVIS |
|---|---|
| Хранить данные многих пользователей | один пользователь, один Mac → локальные файлы |
| Прятать API-ключ разработчика | ключ принадлежит пользователю и лежит в его Keychain |
| Выполнять тяжёлые вычисления | Apple Silicon справляется с STT/TTS/малыми LLM; большие LLM — через официальный API провайдера напрямую |
| Синхронизация между устройствами | пока не требуется (заложено расширение, см. ниже) |
| Раздача обновлений | статический хостинг GitHub Releases + подписанный appcast (Sparkle) — это не наш сервер |

Чем сервер был бы **вреден**: новая точка утечки (голос/команды прошли бы через ещё
одну систему), стоимость и администрирование, зависимость от интернета для базовых функций,
поверхность атаки, юридическая ответственность за чужие данные.

**Будущее расширение.** Всё хранение идёт через протоколы (`SettingsStore`, `MemoryStore`,
`AuditLog`), а сетевой доступ — через провайдеры AI Layer. Если понадобится синхронизация,
добавляется отдельный модуль `Sync` с end-to-end шифрованием (ключ в Keychain), который
работает поверх тех же хранилищ, — без переписывания ядра. Вариант без своего сервера:
CloudKit private database (данные пользователя в его iCloud).

## 7. Модули и зависимости

Вся логика — в локальном Swift Package `Packages/JarvisKit`. Приложение (`App/`) — тонкий
слой: SwiftUI-сцены и composition root. Так модули можно собирать и тестировать
`swift test` без Xcode-проекта.

| Модуль (SPM target) | Ответственность | Зависит от | Фаза |
|---|---|---|---|
| `JarvisCore` | состояния ассистента и машина переходов, `Utterance`/`Sensitive`, privacy-safe логгер, атомарное хранилище и резервные копии, пути данных, журнал аудита и общие типы (источник команды, уровень риска); протоколы голосовых движков добавятся в Phase 2 | — | 1 |
| `JarvisSettings` | модель настроек, значения по умолчанию, хранилище, миграции схемы | Core | 1 |
| `JarvisTools` | `Tool`, `ToolDescriptor`, `ToolRegistry`, валидация аргументов, политика подтверждения | Core | 1 (интерфейсы), 3 (исполнитель) |
| `JarvisAI` | нормализация текста, `WakePhraseMatcher`, `RuleIntentParser`, `ResponseComposer` (личность); в Phase 4 — `HybridRouter` и LLM-провайдеры | — | 2 ✅, 4 |
| `JarvisAssistant` | App Core: протоколы движков, `UtteranceAssembler`, `CommandProcessor`, встроенные инструменты, `AssistantController` | Core, Settings, Tools, AI | 2 ✅ |
| `JarvisVoice` (macOS) | захват звука, `SpeechAnalyzer` + `SpeechDetector`, модели языков, TTS, разрешения, PTT-хоткей, список микрофонов | Core, Settings, Assistant | 2 ✅ |
| `JarvisMac` (macOS) | macOS Integration Layer: адаптеры приложений, файлов, системы, браузера, почты, календаря; Permission Manager; Keychain | Core, Tools | 3 |
| `JarvisMemory` | краткосрочная/долгосрочная память, привычки, пользовательские инструкции | Core | 4 |
| `JarvisAutomation` | сценарии, триггеры, планировщик, история выполнений | Core, Tools, Memory | 4 |

Граф зависимостей ациклический: `Core ← {Settings, Tools, AI} ← Assistant ← Voice ← App`
(в Phase 3–4 добавятся `Mac`, `Memory`, `Automation` по той же схеме).

Модули, которые в таблице помечены будущими фазами, **не создаются заранее пустыми** —
появляются вместе с реальной реализацией.

## 8. Состояния ассистента

```
            enable                     wakeWord / PTT              конец фразы
 Disabled ─────────► Idle(wakeWord | pushToTalk | micPaused) ─────────► Listening ─────────► Processing
    ▲                     ▲   ▲   ▲                                                         │
    │ disable (из ЛЮБОГО) │   │   └──────── speechFinished ── Speaking ◄─────────────────────┤ (ответ без действий)
    └─────────────────────┘   │                                  ▲                          │ план готов
                              │  executionFinished               │                          ▼
                              └────────────────────────────── Executing ◄── approved ── AwaitingConfirmation
                                                                                            │ denied → Idle
  Любое активное состояние ── failed ──► Error ── recover ──► Idle
```

* `disable` разрешён из любого состояния — пользователь всегда может «выдернуть вилку».
* Индикатор микрофона включён только в `Idle(wakeWord)` и `Listening`. macOS дополнительно
  показывает свой оранжевый индикатор, который приложение скрыть не может.
* Privacy Mode — ортогональный флаг, не состояние.

## 9. Хранение данных

| Данные | Где | Формат | Срок |
|---|---|---|---|
| Настройки | `Application Support/JARVIS/settings.json` | JSON со `schemaVersion` | пока пользователь не удалит |
| Память (предпочтения, привычки, инструкции) | `…/memory.json` | JSON | до удаления пользователем; категории можно запретить |
| Сценарии автоматизации | `…/scenarios.json` | JSON | до удаления |
| Журнал аудита | `…/audit/audit-YYYY-MM-DD.jsonl` | JSON Lines | по умолчанию 30 дней, очищается кнопкой |
| API-ключи | macOS Keychain | — | до удаления |
| Резервные копии перед миграцией | `…/backups/` | JSON | последние N |
| **Аудио, расшифровки команд, тексты LLM-диалогов** | **нигде** | — | только RAM на время обработки |

Почему JSON-файлы, а не SQLite/SwiftData: данных мало (сотни записей), файлы прозрачны
(пользователь может их прочитать), миграции тривиальны, ноль зависимостей. При росте
объёма (например, журнал аудита за год) хранилище за протоколом можно заменить на SQLite
(системная `libsqlite3`, без зависимостей).

## 10. Производительность (принципы)

* Event-driven: всё на `async/await` и `AsyncSequence`; никаких таймеров-поллеров.
* Аудиодвижок не работает в состоянии `Disabled` и в режиме «только PTT».
* VAD гейтит STT: тишина не транскрибируется.
* LLM никогда не загружается заранее; локальный сервер выгружает модель по `keep_alive`;
  Apple Foundation Models управляется ОС.
* Модули с тяжёлыми ресурсами создаются лениво (при первом использовании).
* Цели и методика измерений — [PerformanceTargets.md](PerformanceTargets.md).

## 11. Журнал архитектурных решений (ADR)

| # | Решение | Альтернативы | Почему |
|---|---|---|---|
| 1 | Swift 6 + SwiftUI/AppKit, нативно | Tauri, Electron, Flutter | минимум RAM/размера, прямой доступ к Speech/AVFoundation/AX/EventKit, лучшая интеграция с TCC и подписью |
| 2 | macOS 26 (Tahoe) минимум, Apple Silicon — основная цель | macOS 14/15 | `SpeechAnalyzer` (только on-device STT), `SpeechDetector` (VAD), Foundation Models; macOS 27 уже только Apple Silicon |
| 3 | STT: `SpeechAnalyzer` (`SpeechTranscriber`, fallback `DictationTranscriber`); **`SFSpeechRecognizer` запрещён** | SFSpeechRecognizer, whisper.cpp/WhisperKit, облако | новые модули работают только on-device; у SFSpeechRecognizer флаг `requiresOnDeviceRecognition` соблюдается лишь при `supportsOnDeviceRecognition == true`, иначе возможна отправка аудио на сервер |
| 4 | Wake word через VAD + STT + сопоставление фразы | Porcupine, openWakeWord/LiveKit, своя модель | ноль зависимостей, любой язык и фраза; Porcupine требует онлайн-проверки ключа (бесплатные ключи отключены в 2026) |
| 5 | TTS: `AVSpeechSynthesizer` | Piper, облачный TTS | on-device, бесплатно, русские голоса в системе, 0 МБ к размеру |
