# JARVIS — Цели по производительности

**Все цифры ниже — цели и оценки, а не измерения.** Фактические значения появляются в
таблице «Измерено» только после профилирования на реальном Mac, с указанием железа,
версии macOS и сборки. Ничего не выдумываем.

Эталонное железо: MacBook Pro M1 Pro / M2 Pro, 16 ГБ RAM, macOS 26+.

## 1. Цели

| Метрика | Цель | Как измеряем |
|---|---|---|
| Размер `JARVIS.app` (Release, без локальной LLM) | ≤ 15 МБ | `du -sh` в CI (отчёт в логе) |
| Холодный запуск до иконки в меню | ≤ 1 с | `os_signpost` + Instruments (App Launch) |
| Завершение | ≤ 0,5 с | замер времени `terminate` |
| RAM, ассистент выключен | ≤ 50 МБ (phys footprint) | `footprint`, `vmmap --summary`, Activity Monitor (Memory) |
| CPU, ассистент выключен | ≈ 0% (нет пробуждений) | Activity Monitor «Idle Wake Ups», Instruments Energy Log |
| RAM, режим wake word, тишина | ≤ 120 МБ | то же |
| CPU, режим wake word, тишина | ≤ 2% одного ядра (среднее за 5 мин) | `top -l`, Instruments Time Profiler |
| CPU, режим wake word, речь рядом | ≤ 15% одного ядра (среднее) | то же, сценарий «подкаст рядом» |
| Wake word → сигнал «слушаю» | ≤ 400 мс | signposts |
| Конец фразы → начало действия (правило) | ≤ 600 мс | signposts |
| Конец фразы → начало действия (локальная LLM 3–4B) | ≤ 2,5 с | signposts |
| Конец фразы → начало действия (облако) | ≤ 3 с при хорошей сети | signposts |
| Начало речи TTS | ≤ 300 мс после готовности ответа | signposts |
| RAM при работе локальной LLM | модель ≈ 2,5–3 ГБ в процессе сервера; JARVIS +≤ 30 МБ | `footprint` обоих процессов |
| Выгрузка LLM после простоя | ≤ 5 мин | настройки сервера / наблюдение |
| Энергия в режиме wake word | «Low» в Activity Monitor (Energy Impact) | Activity Monitor, `powermetrics` |

## 2. Оценки потребления по режимам (до измерений)

| Режим | RAM (оценка) | CPU (оценка) | Почему |
|---|---|---|---|
| Выключен | 30–50 МБ | ~0% | SwiftUI-агент без таймеров и аудио |
| Только PTT, ожидание | 30–50 МБ | ~0% | микрофон закрыт |
| Wake word, тишина | 60–120 МБ | 1–2% | аудиодвижок + RMS/VAD; STT не работает в тишине |
| Wake word, речь рядом | 80–150 МБ | 5–15% | потоковое on-device STT (часть нагрузки — в системных процессах Speech; учитывать их тоже) |
| Обработка правилом | +0 | кратковременный пик | парсинг текста |
| Apple Foundation Models | память — в системном процессе | пик на Neural Engine/GPU | управляется ОС |
| Ollama + 4B 4-bit | +2,5–3 ГБ (в процессе Ollama) | пик GPU 1–3 с | выгружается после простоя |

Важно: часть работы распознавания речи выполняют системные процессы macOS, поэтому при
замерах учитываем не только процесс JARVIS, но и связанные системные процессы.

## 3. Методика

1. Release-сборка, подписанная стабильным сертификатом, запущенная из `/Applications`.
2. Прогрев 2 мин, затем замер 5 мин; три прогона; фиксируем медиану.
3. Сценарии: тишина; подкаст на соседнем устройстве; 20 команд подряд; 10 команд через LLM.
4. Инструменты: Instruments (Time Profiler, Allocations, Leaks, Energy Log, os_signpost),
   `footprint -p`, `top -l 0 -s 5 -pid`, `powermetrics --samplers cpu_power` (нужен sudo —
   только по согласию пользователя).
5. Signposts в коде: `wake.detected`, `utterance.end`, `plan.ready`, `action.start`,
   `tts.start` (имена — статические строки, без содержимого команд).
